## Interpretation notes

- Generic cache (1) and LLM KV cache offload (18) are deliberately distinct. If KV cache meant ordinary key/value caching instead, item 18 should be renamed and the inference diagram removed, without silently dropping a requested label.
- “Chats put-sub” is normalized to “Chats / Pub/Sub.” Live delivery and stored history are separate concerns.
- Fraud screening is an illustrative application of probabilistic membership, not a measured or built-in fraud-detection capability. Membership positives require exact verification before adverse decisions.
- Core implementation suggestions such as counter-based IDs are architectural mappings, not claims that the reviewed documentation guarantees every stated outcome. Review failure behavior for the actual deployment.
- JSON, Search, Bloom and LDAP are module features. Do not infer that a stock server has them loaded, or that the modules are compatible with every release on the release board.
