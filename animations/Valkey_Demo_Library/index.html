20 Valkey use cases

72 six-step scenarios, including multiple sources of truth, semantic answers and LLM attention KV tensors.

  • U01Query and result cachingThe application retrieves original data and decides how to store, reuse and invalidate it.↗
  • U02Shared session storeAny application instance can load the same server-side session from one shared record.↗
  • U03Distributed coordination with locksOne worker claims temporary ownership of a task while the others defer or retry.↗
  • U04Atomic countersConcurrent instances increment one shared number without their own read-modify-write.↗
  • U05Distributed rate limitingSeveral gateways enforce one shared request budget instead of one budget each.↗
  • U06Shared sequence allocationA shared atomic counter hands consecutive numbers to many services during normal operation.↗
  • U07Work queues with StreamsDelivered jobs stay pending until acknowledged, so failed work can be reclaimed.↗
  • U08Real-time leaderboardsA sorted set keeps members ordered by score as updates arrive.↗
  • U09Recent time-series and rolling metricsA hot window of recent observations modelled with core data types, backed by an archive.↗
  • U10Live chat and notificationsOne publish reaches every subscribed gateway, which forwards to its own connected users.↗
  • U11Idempotency and duplicate-request controlRetries of the same operation converge on one record instead of repeating the side effect.↗
  • U12Replayable event log with StreamsSeveral applications read the same retained event history at their own speed and position.↗
  • U13Shared real-time infrastructure for servicesEach service uses a specific Valkey facility while keeping its own authoritative database.↗
  • U14JSON document storage with JSONPath accessThe server understands structure, so a nested field changes without rewriting the whole value.↗
  • U15Full-text search over indexed documentsText matching combines with tag and numeric filters to select documents by content.↗
  • U16Vector storage and similarity searchStored vectors plus a query vector return nearest candidates under a chosen distance metric.↗
  • U17Probabilistic membership with Bloom filtersA compact filter rules items out cheaply and sends only possible matches to the exact source.↗
  • U18Object and key-value cachingOne reusable object, many possible authorities: SQL, NoSQL, object/file stores or an API.↗
  • U19Semantic caching for AI responsesA reworded question reuses an answer only when scope, distance, and validity rules all permit it.↗
  • U20LLM inference: shared KV tensor cacheReuse exact-prefix attention state; Valkey holds bytes, while GPU memory holds active tensors.↗
